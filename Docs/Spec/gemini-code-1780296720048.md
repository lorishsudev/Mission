## 1. 專案願景與目標 (Vision & Goals)
打造一個跨平台、去中心化的「現實生活任務/成就」遊戲化平台 (Gamification as a Service, GaaS)。

**MVP 階段核心策略：**
由官方主導內容生產，設計多關卡、結合地理位置與現地解謎的經典任務（如：全台老廟巡禮、城市密室逃脫）。使用者透過行動端 App 進行實地闖關、利用照片 GPS 與文字問答自動驗證，通關後可收集虛擬榮譽勳章並分享至個人網頁，以此驗證核心商業模式與用戶黏著度。

---

## 2. 系統架構與技術棧 (Tech Stack & Infrastructure)

| 模組分工 | 技術棧選型 | 部署平台 | MVP 狀態 |
| :--- | :--- | :--- | :--- |
| **挑戰者行動端 App** | React Native (Expo) (iOS / Android) | Expo (EAS) | `核心開發` |
| **個人紀錄與榮譽牆 Web** | Next.js (提供外部公開分享網址，支援 RWD) | Vercel | `核心開發` |
| **後端服務與數據庫** | Supabase (PostgreSQL + Auth 認證) | Supabase Cloud | `核心開發` |
| **圖片與檔案儲存** | **Supabase Storage** (建立 `challenge-uploads` 與 `badges` 儲存桶) | Supabase Cloud | `核心開發` |
| **任務管理/審核後台** | Supabase Dashboard (直接操作 DB) | Supabase | `未來演進 (MVP僅留結構)` |

> 💡 **優勢說明：** 改用 Supabase Storage 後，可直接利用 Supabase 的資料庫策略 (RLS) 來保護使用者上傳的檔案。同時，核心的邏輯與儲存都在同一個雲端網路內，能降低網路延遲並簡化 API 金鑰的管理。

## 3. 領域模型與資料庫設計 (DB Schema)
核心結構維持樹狀三層架構：**任務 (Missions) ➔ 關卡 (Stages) ➔ 挑戰 (Challenges)**。資料庫已預留未來管理後台所需之狀態欄位。

```sql
-- 1. 大任務表 (由官方手動預入，EX: 台北捷運尋寶線)
CREATE TABLE missions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(255) NOT NULL,            
    description TEXT,
    badge_image_url VARCHAR(512),           -- 通關虛擬獎章圖片網址 (儲存於 Supabase Storage 'badges' bucket)
    bonus_perk_url VARCHAR(512),            -- (選填) 實體紀念品兌換或加購連結
    status VARCHAR(50) DEFAULT 'published', -- published (直接公開), draft, archived
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. 關卡表 (EX: 捷運大安森林公園站)
CREATE TABLE stages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    mission_id UUID REFERENCES missions(id) ON DELETE CASCADE,
    title VARCHAR(255) NOT NULL,            
    sequence INT NOT NULL,                  -- 關卡排序 (1, 2, 3...)
    is_sequential BOOLEAN DEFAULT TRUE,     -- 是否必須依序解鎖
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 3. 挑戰項目表 (最小驗證單元，EX: 與特定公共藝術品合照)
CREATE TABLE challenges (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    stage_id UUID REFERENCES stages(id) ON DELETE CASCADE,
    title VARCHAR(255) NOT NULL,            
    type VARCHAR(50) NOT NULL,              -- 'GPS_PHOTO' 或 'TEXT_QUESTION'
    -- 驗證條件欄位：使用 JSONB 確保未來類型擴充性
    -- GPS_PHOTO 範例: {"latitude": 25.0298, "longitude": 121.5362, "radius_meters": 30}
    -- TEXT_QUESTION 範例: {"question": "雕像基座寫了哪四個字？", "accepted_answers": ["光輝歲月", "光輝"] }
    verification_criteria JSONB NOT NULL,   
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 4. 使用者任務整體進度表
CREATE TABLE user_mission_progress (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL,                  -- 關聯至 Supabase Auth User
    mission_id UUID REFERENCES missions(id) ON DELETE CASCADE,
    status VARCHAR(50) DEFAULT 'in_progress', -- in_progress, completed
    completed_at TIMESTAMP WITH TIME ZONE,
    UNIQUE(user_id, mission_id)
);

-- 5. 使用者挑戰提交歷史紀錄表（預留 verification_status 供未來人工審核擴充）
CREATE TABLE user_challenge_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL,
    challenge_id UUID REFERENCES challenges(id) ON DELETE CASCADE,
    submitted_text TEXT,                    -- 問答題答案
    submitted_file_url TEXT,                 -- 照片題 Supabase Storage 檔案網址
    is_passed BOOLEAN DEFAULT FALSE,        -- 自動/手動驗證結果
    verification_status VARCHAR(50) DEFAULT 'auto_verified', -- auto_verified, pending_review, manual_approved, manual_rejected
    verified_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
