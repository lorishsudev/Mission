1. 專案願景與目標 (Vision & Goals)

打造一個跨平台、去中心化的「現實生活任務/成就」遊戲化平台 (Gamification as a Service, GaaS)。

MVP 階段核心策略：由官方主導內容生產，設計多關卡、結合地理位置與現地解謎的經典任務。使用者透過行動端 App 進行實地闖關、利用照片 GPS 與文字問答自動驗證，通關後可收集虛擬榮譽勳章並分享至個人網頁，以此驗證核心商業模式與用戶黏著度。

3. 領域模型與資料庫設計 (DB Schema)

核心結構維持樹狀三層架構：任務 (Missions) ➔ 關卡 (Stages) ➔ 挑戰 (Challenges)。

-- 1. 大任務表 (由官方手動預入)
CREATE TABLE missions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(255) NOT NULL,            
    description TEXT,
    badge_image_url VARCHAR(512),           -- 儲存於 Supabase Storage 'badges' bucket
    bonus_perk_url VARCHAR(512),            -- (選填) 實體紀念品兌換或加購連結
    status VARCHAR(50) DEFAULT 'published', -- published, draft, archived
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. 關卡表
CREATE TABLE stages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    mission_id UUID REFERENCES missions(id) ON DELETE CASCADE,
    title VARCHAR(255) NOT NULL,            
    sequence INT NOT NULL,                  -- 關卡排序 (1, 2, 3...)
    is_sequential BOOLEAN DEFAULT TRUE,     -- 是否必須依序解鎖
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 3. 挑戰項目表 (最小驗證單元)
CREATE TABLE challenges (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    stage_id UUID REFERENCES stages(id) ON DELETE CASCADE,
    title VARCHAR(255) NOT NULL,            
    type VARCHAR(50) NOT NULL,              -- 'GPS_PHOTO' 或 'TEXT_QUESTION'
    -- 驗證條件欄位：使用 JSONB 確保未來類型擴充性
    verification_criteria JSONB NOT NULL,   
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 4. 使用者任務整體進度表
CREATE TABLE user_mission_progress (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL,                  -- 關聯至 Supabase Auth User
    mission_id UUID REFERENCES missions(id) ON DELETE CASCADE,
    status VARCHAR(50) DEFAULT 'in_progress', -- in_progress, completed
    completed_at TIMESTAMP WITH TIME ZONE,
    UNIQUE(user_id, mission_id)
);

-- 5. 使用者挑戰提交歷史紀錄表
CREATE TABLE user_challenge_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL,
    challenge_id UUID REFERENCES challenges(id) ON DELETE CASCADE,
    submitted_text TEXT,                    -- 問答題答案
    submitted_file_url TEXT,                 -- 照片題 Supabase Storage 檔案網址
    is_passed BOOLEAN DEFAULT FALSE,        -- 自動/手動驗證結果
    verification_status VARCHAR(50) DEFAULT 'auto_verified', 
    verified_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

4. MVP 核心業務邏輯與演算法規範

📌 挑戰者 App 端：原始照片上傳與驗證流程

  • 防作弊機制： App 調用原生相機上傳原圖至 Supabase Storage challenge-uploads 桶，不可進行任何消除 EXIF Metadata 的壓縮。
  • 後端解析： 後端服務（或 Edge Functions）下載該照片片段並利用套件提取 GPSLatitude 與 GPSLongitude。

📌 後端自動驗證邏輯：哈弗辛公式 (Haversine Formula)

當挑戰類型為 GPS_PHOTO 時，計算照片經緯度 (lat1, lon1) 與目標點 (lat2, lon2) 的地球弧度距離 d：

d = 2 * R * arcsin( sqrt( sin²(Δlat/2) + cos(lat1) * cos(lat2) * sin²(Δlon/2) ) )
  • 地球平均半徑 R = 6,371,000 公尺。距離 d ≤ radius_meters 則判定通過。
